# Fase 3 — Design System & Public Shell

Fuente: `docs/PROJECT_BLUEPRINT.md` §11 ("Design System & Public Shell — UX premium, navegación, responsive, accessibility baseline"). Iniciada 2026-08-08.

**Nota de proceso**: este documento se escribe al cierre de la fase, no al inicio (desviación del patrón seguido en Fase 2). La fase se construyó directamente a partir del blueprint y de instrucciones explícitas del propietario funcional (uso obligatorio de la skill `/impeccable` para todo el trabajo de diseño; requisito de soporte multi-idioma agregado a mitad de fase). Se documenta el scope retroactivamente para no perder trazabilidad, pero el orden real de ejecución está en `docs/phases/P3_REPORT.md`.

## Scope

- Design tokens propios (color OKLCH, tipografía, spacing, radii, z-index, motion) vía Tailwind v4 `@theme`.
- Navigation shell: header con nav primaria, búsqueda, menú móvil; footer con links legales y de verticales.
- Core page templates: Home, Discover (índice de verticales), vertical hub (`/[site]`), Search, y las 5 páginas legales (About/Methodology, Editorial Policy, Affiliate Disclosure, Privacy, Terms).
- Responsive real (mobile/tablet/desktop) y accessibility baseline WCAG AA (skip-link, focus-visible, reduced-motion, aria-labels, contraste verificado).
- **Internacionalización del sitio público** (agregado a mitad de fase, fuera del blueprint original que asumía audiencia US/inglés): 4 idiomas — inglés, español, portugués, hindi.

## Explícitamente fuera de scope (no adelantar)

- Contenido editorial real (comparativas, guías) — placeholder únicamente ("en desarrollo activo"); catálogo real es Fase 4.
- UI de cuenta de usuario o de admin — no existen rutas admin/user todavía; backlog 204 (route guards) se re-difiere a Fase 4, que es donde esas rutas se crean por primera vez.
- Motion avanzado más allá de transiciones de color/opacity en hover/focus — animaciones de entrada/reveal no eran necesarias para el shell estático actual.
- Traducción de contenido editorial — el diccionario de Fase 3 cubre únicamente el shell público (nav, footer, home, discover, legal), no contenido de comparativas (no existe todavía).

## Entregables (según blueprint + instrucción explícita de i18n)

- Design tokens (`apps/web/src/app/globals.css`, Tailwind v4 `@theme`).
- Header/Footer/Search shell, responsive, con language switcher.
- Templates: Home, Discover, vertical hub, Search, 5 páginas legales.
- Sistema de i18n tipado (4 idiomas) — `apps/web/src/lib/i18n/`, `middleware.ts`.
- `docs/DESIGN_SYSTEM.md`.

## Auditoría de cierre

No toca Auth/RBAC/RLS/secrets/monetization (matriz de independencia de `PROJECT_BLUEPRINT.md` §10.1), por lo que **no es una zona de riesgo obligatoria bajo ADR-011**. Aun así, se ejecuta auditoría de agente independiente por ser parte del Definition of Done de toda fase (`CLAUDE.md` — "Tests + PHASE_REPORT.md + auditoría de agentes especializados"), con foco en A2 (UX/consistencia), A4 (QA/responsive/a11y) y verificación específica de que no queden strings hardcodeados en un solo idioma fuera del diccionario.
