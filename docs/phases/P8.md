Fuente: `docs/PROJECT_BLUEPRINT.md` §9 ("Adquisición diversificada... GEO/AEO/LLM citations") y §11 (roadmap, Fase 8: "SEO/GEO/AEO, sitemaps/schema, social content ops, newsletter/alerts"). Iniciada 2026-08-11, a pedido explícito del propietario funcional: que cada página se revise para maximizar cómo la ven buscadores, LLMs y cualquier sistema de búsqueda — no como una tarea puntual, sino como práctica a mantener en cada página futura.

## Bloqueo real descubierto al iniciar: no hay dominio propio todavía

`packages/shared/src/branding.ts` tiene `domain: ""` — backlog 109 (registro de dominio) sigue diferido, sin fecha antes de Fase 11. Toda URL canónica/sitemap/hreflang necesita una base absoluta real. **Decisión**: se usa la URL real de producción de Vercel (`jprs-monetization-platform-web.vercel.app`, confirmada pública en esta sesión) como base, resuelta en código vía `NEXT_PUBLIC_SITE_URL` con fallback a `VERCEL_PROJECT_PRODUCTION_URL` (variable que Vercel expone automáticamente) — nunca hardcodeada como string literal, para que cambiar a un dominio propio cuando 109 se resuelva sea un cambio de una sola variable de entorno, no una búsqueda y reemplazo por el código.

## Scope real de esta sesión

- **801 (metadata/canonical/robots)**: `app/robots.ts` (Next.js nativo); cada una de las 16 páginas existentes obtiene `description` real (reutilizando copy editorial ya existente en los diccionarios/DB — nunca texto inventado nuevo), `alternates.canonical`, y `alternates.languages` (hreflang para los 5 locales + `x-default`).
- **802 (sitemaps)**: `app/sitemap.ts` (Next.js nativo, dinámico) — incluye las rutas estáticas del shell, y consulta Supabase en tiempo de build/request por categorías, productos y contenido `published` de los 3 sites lanzados, en los 5 locales.
- **803 (structured data)**: `packages/seo` (placeholder vacío desde Fase 1, primera vez con contenido real) — `Organization`/`WebSite` JSON-LD sitewide, `Product` JSON-LD en perfiles de producto (precio/moneda/disponibilidad reales, nunca inventados), `BreadcrumbList` JSON-LD en categoría/producto/guía.
- **804 (internal linking/breadcrumbs)**: breadcrumb visible (no solo "← Volver") en categoría/producto/guía, mismos datos que alimentan el `BreadcrumbList` JSON-LD — evita mantener dos fuentes de verdad para la misma jerarquía.
- **Práctica hacia adelante** (lo que pide el propietario funcional, más allá de esta sesión): toda página nueva que se cree de aquí en adelante debe pasar por esta misma revisión (metadata real, canonical, hreflang, schema aplicable) antes de darse por completa — no es un checklist que se corre una vez y se olvida.

## Explícitamente fuera de scope

- **805 (newsletter/preferences) y 806 (social content workflow)** — son canales de distribución, no señales de descubribilidad para buscadores/LLMs; quedan para cuando el propietario funcional priorice adquisición activa por esos canales.
- **`llms.txt`** (estándar emergente, no oficial, sin consenso todavía) — se evalúa cuando su adopción sea más clara; el schema.org estructurado ya cubre la señal más establecida para que un LLM entienda de qué trata cada página.
- **Verificación real en Google Search Console / Bing Webmaster Tools** — requiere que el propietario funcional registre la propiedad (cuenta externa), fuera del alcance de un agente autónomo.
- **Contenido nuevo para mejorar posicionamiento** (eso es backlog 607/617/627, ya documentado) — esta fase es la capa técnica que hace descubrible el contenido que ya existe, no genera contenido nuevo.
